## Not implemented yet

| Item | Why it matters |
|---|---|
| ❌ C++ / ObjC **exception unwinding** (`@try`, `throw`) | needs an unwinder for Mach-O `__unwind_info` / `__eh_frame`; today a throw ends the app with a message |
| ❌ Microphone input (RemoteIO input bus records silence) | recording apps |
| ❌ `AudioConverter`, `ExtAudioFile`, `AudioFile` | audio import/export |
| ❌ Software keyboard / text input | text fields can be shown but not typed into |
| ❌ Multi-touch (pinch, rotation) | the bridge forwards one pointer |
| ❌ Networking (`NSURLSession`/`NSURLConnection` fail like an offline device), sockets | online features |
| ❌ Remote web pages and JavaScript (`UIWebView` lays out bundled HTML natively; there is no browser engine) | web-based screens |
| ❌ Auto Layout (NIB/storyboard frames are used as laid out; constraints are ignored) | modern app UIs on other screen sizes |
| ❌ dylibs / embedded frameworks (`MH_DYLIB`), Swift runtime | modern apps |
| ❌ OpenGL ES / GLKit (next phase: on Android's own GLES) | most games |
| ❌ Core Data, sqlite3, NSPredicate evaluation (later phase) | data-driven apps |
| ❌ 32-bit (armv7) apps | would need CPU emulation (touchHLE's domain) |
| ❌ FairPlay-encrypted App Store binaries | DRM: only user-decrypted or self-built binaries can run |

## So what does the APK run?

* The bundled demo apps (their own source in `samples/`): **Graphics Demo**
  (drawing, layers, animation, paging, gestures, controls, alert), **NIB Demo**
  (a view controller loaded from a compiled NIB), a UIKit counter, an
  Objective-C tour (also built for iOS 14 with chained fixups), a plain C
  program and a RemoteIO sine generator.
* Unencrypted arm64 iOS apps whose API use is covered (see
  `runtime/src/exports/*.def`; `sdk/` builds such apps without Apple's SDK).
  Missing functions return 0 / nil and are logged once instead of stopping the
  app, so partially covered apps can still get far.
* The reference app from the stage-2 work (see `LOOPY-REQUIREMENTS.md`) starts,
  shows its main screen from its own NIBs and images, and reacts to taps
  (recording starts in its audio engine); its control screen, settings (with
  nested pages), sessions, recordings and HTML help open and navigate; audio
  input is still silent.
